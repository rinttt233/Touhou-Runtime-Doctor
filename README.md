# 东方 Project 运行环境医生 (Touhou Runtime Doctor)

一个给 Windows 用的**离线、免安装、可回滚**的东方 Project 运行环境体检与修复工具。

它的目标不是"再做一个 DirectX 修复工具"，而是回答一个更具体的问题：

> 这台机器上，东方永夜抄（以及 th06～th19）为什么跑不起来？
> 如果跑得起来但手感不对（比如键盘暴走），又是哪里出的问题？

---

## 这个仓库是什么形态

**本仓库收录工具的完整源码（含抓取脚本），但不含离线载荷本身。**

| 项目 | 是否在仓库里 | 说明 |
| --- | --- | --- |
| 工具源码（`lib\`、`Run.ps1`、各 `.bat` 等） | **在** | 完整可用 |
| `tools/Fetch-OfflinePack.ps1` | **在** | 在**有网络**的机器上一键抓齐载荷的脚本 |
| `offline/` 载荷（约 520 MB） | **不在** | 各类 VC++ 运行库安装包、DirectX 官方运行库与 DLL、第三方工具包。体积大，且属于微软/第三方的可再分发组件，不适合放进 Git |

也就是说：仓库里放的是**下载这些库的脚本**，而不是库本体。

### 怎么把载荷备齐

在一台**能联网**的机器上克隆本仓库，然后：

```powershell
powershell -ExecutionPolicy Bypass -File tools\Fetch-OfflinePack.ps1 -List    # 先看缺什么，不做改动
powershell -ExecutionPolicy Bypass -File tools\Fetch-OfflinePack.ps1 -All     # 抓齐全部（15 个包）
```

抓完把**整个文件夹**拷到离线的目标机器，双击 `自检.bat`，再双击 `一键修复.bat`。

脚本的安全设计：先下到 `.part` 临时文件、校验通过才改名（断网不会留下半截文件）；
每个包核对 SHA256，清单里没写哈希的会在下载后自动算出并**回写清单**（自封），
之后每次抓取都校验；微软/第三方的二进制额外做 Authenticode 签名校验。

如果目标机器完全无法联网、也没有中转机器，那就只能手工获取安装包放进 `offline\`。
工具会自己识别这种形态：当 `tools\Fetch-OfflinePack.ps1` 不存在时，
所有提示语会自动改成"请手工获取安装包放进 offline\ 目录"，不会给出指向不存在文件的空指引。

因此能力边界是：

- **体检、诊断、启动验证：完整可用。** 不依赖任何载荷。
- **不需要外部文件的修复：完整可用。** 例如兼容性标志、注册表开关、DirectInput 重置、路径迁移、文件解锁等。
- **需要"补一个 DLL / 装一个运行库"的修复：先跑一次抓取脚本即可完整可用。**
  没抓载荷时也会明确告诉你缺什么、去哪儿取。

## 快速开始

1. 下载本仓库（`Code` → `Download ZIP`，或 `git clone`）。
2. 双击 **`一键修复.bat`**。
   - 会依次执行：环境体检 → 生成修复计划 → 执行修复 → 启动游戏验证。
   - 需要管理员权限的修复项在非管理员下会被**跳过并说明**，不会静默失败。
3. 看结果。报告会同时生成 `修复报告.txt`（记事本可直接打开）和 `修复报告.html`（带颜色分级）。

其它入口：

| 文件 | 作用 |
| --- | --- |
| `一键修复.bat` | 体检 + 修复 + 启动验证（推荐） |
| `仅体检.bat` | 只体检、不改动任何东西 |
| `设备信息.bat` | 输出整机设备信息（文本 / HTML / JSON），与游戏无关也能用 |
| `自检.bat` | 实测工具自身在当前机器上的能力是否可用 |
| `回滚.bat` | 撤销上一次修复的全部改动 |

命令行（想指定某一份游戏时）：

```powershell
powershell -ExecutionPolicy Bypass -File Run.ps1 -Mode Auto -GamePath "D:\game\[th08] 东方永夜抄 (汉)"
```

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 7 / 8 / 8.1 / 10 / 11，**32 位与 64 位都支持** |
| PowerShell | **3.0 以上**（推荐 5.1） |
| 网络 | **不需要**（本工具全程离线） |
| 安装 | 免安装，解压即用 |

Windows 7 出厂只带 PowerShell 2.0，需要先装 WMF 5.1。
工具启动前会主动检测 PowerShell 版本与系统位数，版本不够时给出明确提示，
而不是抛出一堆看不懂的语法错误。

## 它能查出什么

体检结论按 **严重 / 高 / 中 / 低 / 正常** 分级，每条都附带**证据**与**处理建议**。

| 分类 | 覆盖内容 |
| --- | --- |
| 运行环境 | 系统位数、PowerShell 版本、SysWOW64 是否存在、管理员权限 |
| 依赖完整性 | **解析游戏 exe 的 PE 导入表**，逐个确认依赖 DLL 能否找到（含 ApiSet 识别与调试变体名过滤） |
| DirectX | 111 项组件清单、d3dx9/d3dcompiler/XAudio2/XInput 落地情况、Direct3D/DirectDraw 硬件加速开关 |
| VC 运行库 | 2005/2008/2010/2012/2013/2015-2022，x86 与 x64 **分别**核实（同时看注册表、系统目录、WinSxS 三处证据） |
| 路径与目录 | 中文/日文/方括号路径、只读属性、权限、路径长度 |
| 显示与兼容性 | 分辨率与刷新率、兼容性标志、DPI、全屏优化 |
| 文件安全标记 | 从网盘/压缩包解出的文件常带的"来自其他计算机"标记（MotW） |
| 游戏配置 | 帧率上限与实际刷新率的匹配（vpatch 的 `GameFPS`） |
| 字体 | 游戏所需字体是否存在 |
| 显卡与驱动 | 驱动版本与日期、是否存在已知有问题的老驱动 |
| 音频 | 音频设备与驱动状态 |
| 系统服务与策略 | 影响游戏的服务（如 MSI 服务）、策略限制 |
| 冲突软件 | 已知会干扰老游戏的常驻进程、安全软件 |
| 游戏文件 | 主程序与数据文件是否齐全、是否被改动 |
| 输入子系统 | 见下节 |

## 键盘暴走专项

"进游戏后键盘像被按住不放、角色一直往一个方向跑"是东方玩家最常见也最难查的问题。
本工具为它做了专门的一整套检测，并且**刻意不去猜**——每一项都给出可复核的原始数据：

- **输入法 / 键盘布局**：是否只有中文键盘布局而没有英文布局（这是本机实测的首要原因）。
  中文输入法在 DirectInput 独占全屏下会持续吞键、重复送键，而用户又切不出去。
- **辅助功能**：粘滞键、筛选键、切换键、鼠标键是否被开启（Flags 的**最低位**判定，而不是"非零即开"）。
- **内核级按键重映射**：`Scancode Map` 是否存在及其原始字节。
- **过滤驱动**：键盘/鼠标设备类栈里是否挂了第三方驱动。
  **判定依据是驱动的微软数字签名，不是硬编码白名单**——白名单会把正常机器误报成有问题。
- **虚拟/转换键盘设备**：例如 `HID\CONVERTEDDEVICE` 这类由外设软件造出来的假键盘。
- **手柄/控制器**：摇杆漂移会被很多老游戏当成持续方向输入。
- **按键重复率**：`KeyboardSpeed` / `KeyboardDelay`。
- **显示时序**：高刷新率显示器 + 无帧率上限导致的输入采样异常。

此外会导出一份**输入诊断快照 JSON**（同时放进 `报告\` 目录），
里面是上述各项的原始数据而不只是结论，方便后续分析或接入插件。

## 自动修复项

所有修复都满足两条硬性约束：**先备份、可回滚**。

- 文件类改动：改动前整文件备份到 `backup\<时间戳>\`。
- 注册表改动：整分支导出**加上**逐值记录。
  只做整分支导出是**不完备的**——`reg import` 只能合并/覆盖，无法删除"修复过程中新增的值"，
  于是回滚后新增项会残留，用户以为已经还原、其实没有。
  因此每个值单独记一条日志：原本不存在→回滚时删除；原本存在→回滚时写回原值与原类型。

修复项包括：部署/补齐 DirectX 组件、VC 运行库安装、兼容性标志、重置 DirectInput 映射、
禁用辅助功能快捷键、添加英文键盘布局、移除 Scancode Map、硬件加速开关、
解锁文件安全标记、目录只读与权限、迁移到纯 ASCII 路径、字体安装、音频服务、
MSI 服务、安全软件排除项、生成启动器、部署 dgVoodoo2 / Locale Emulator（如提供）。

## 开发者须知（几个真实的坑）

这些不是理论风险，是在开发过程中实际踩到并修掉的，改代码时请勿退化：

1. **`.ps1` 必须是 UTF-8 带 BOM。**
   中文 Windows 上的 PowerShell 5.1 会把**无 BOM** 的 UTF-8 当 GBK 解码，
   中文变乱码并直接破坏语法——脚本在本工具自己的错误处理跑起来之前就已经解析失败了。
   `Run.ps1` 因此写成纯 ASCII，并在启动时自愈 BOM。

2. **32 位进程在 64 位系统上会被静默重定向。**
   `C:\Windows\System32` 会被改写成 `SysWOW64`，
   `HKLM\SOFTWARE\...` 会被改写成 `SOFTWARE\WOW6432Node`，两者都不报错。
   后果是"以为在查 64 位组件，实际查的是 32 位文件"，最后输出一份看着正常、结论全错的报告。
   处理方式：入口脚本优先用 `Sysnative` 拉起**原生位数**的 PowerShell；
   系统目录统一走 `Get-TrdSystemDir`；注册表统一用 `OpenBaseKey` 显式指定视图。

3. **不要硬编码 `SysWOW64`。**
   32 位 Windows 上根本没有 WOW64 层，32 位 DLL 就在 `System32` 里。
   硬编码会让工具把所有组件都报成缺失，把一台健康的 32 位机器判成需要大修。

4. **注册表读写不要依赖进程默认视图。**
   VC++ 运行库是分位数注册的，x64 那份在 64 位视图、x86 那份在 32 位视图。
   依赖默认视图会漏掉一半证据，进而误报"VC 运行库缺失"并触发毫无必要的重装。

5. **`Start-Process -PassThru` 的 `ExitCode` 不可靠**（成功也可能返回 -1），
   需要真实退出码时用 `Invoke-TrdProcess`。

## 关于本工具的验证状态（如实说明）

**已实测**：Windows 11 家庭中文版（Build 26200）、64 位、PowerShell 5.1。
在这些条件下完成了自检 12/12、完整体检、一键修复、以及**东方永夜抄启动验证**（成功创建游戏窗口）。

**已做静态审计但未在真机执行**：

- Windows 7 / 8 / 8.1 与 32 位 Windows：按 32 位路径设计与审计，未在真机跑过。
- PowerShell 3.0 / 4.0：所有 PS5 专有 cmdlet（`Get-FileHash`、`Expand-Archive`、`Get-CimInstance`）
  都有降级实现，并已确认代码中不含 PS7 专有语法、PS4+ 的 `.Where{}` 方法语法或 .NET Core 专有 API。
  但没有可用的 3.0/4.0 环境做实跑。

**一个容易忽略的保证**：由于所有系统目录与注册表访问都经过统一的位数抽象层，
工具在 32 位与 64 位 PowerShell 下会给出**逐条完全一致**的结论；
这不是推断，是比较过输出的。

## 第三方组件

本仓库**不包含**任何第三方二进制文件。工具在运行时会读取你本机已安装的组件，
并在你自行提供了相应文件时调用它们：

- Microsoft Visual C++ Redistributable（微软，可再分发）
- Microsoft DirectX End-User Runtime / DirectX SDK 中的 D3DX 系列（微软）
- dgVoodoo2（作者 Dege）—— DirectX 8/9 转 Direct3D 11 的封装层
- Locale Emulator（作者 xupefei）—— 转区运行

这些组件各自的许可条款由其作者决定，本工具只做调用与状态检测，不重新分发。
